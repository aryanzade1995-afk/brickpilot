# Ray-traced massing

Open **3D massing → Realistic house view**. There is one **Interactive** view, with automatic ray-traced refinement when the camera and traffic are still. The current visible house, live facade, services, solar, parked car and neighbourhood are sampled into a read-only scene snapshot. Dragging immediately uses the responsive raster view; the image accumulates again after the camera stops. **View quality** holds Balanced, Fine and Photo detail choices in a compact disclosure. No rendering-mode switch is required. Traffic starts paused; **Play traffic** uses live raster lighting, while **Pause traffic** automatically rebuilds the still scene and resumes light refinement. Unsupported enhanced lighting falls back to the interactive render.

Balanced accumulates 64 samples per pixel; Fine accumulates 128; Photo accumulates 384 with gentler noise reduction. Progress reports actual completed samples, not a timed percentage. Eight light bounces, ten transmission bounces, photographed HDR lighting and an edge-aware noise-reduction pass provide indirect light, reflections and soft shadows. Daylight and golden hour rebuild the lighting. Photographic mode samples the actual sky instead of adding a second distant artificial sun, which caused non-finite grazing samples on the tested Intel GPU. The default realistic presentation uses dawn/dusk lighting and a closer architectural camera.

Realistic mode loads locally bundled, checksum-verified CC0 Poly Haven HDRIs and surface maps, plus ambientCG Grass 008 lawn maps. Selected exterior paint colours and existing material images stay intact. Plaster and paving receive surface detail; transmissive glazing uses neutral clear-glass response rather than a dark alpha tint. The original studio materials restore when leaving Realistic mode. The existing furnished-room pipeline supplies visible interior furniture and warm ceiling emitters in up to six living/bed/dining rooms; no walls or floor layout are recreated. Detailed Ferrari geometry replaces the block-style road cars, and optimized scanned tree and shrub models supply the planting. These presentation elements do not change specifications or the BOQ.

The ray tracer samples the same local HDR environment and room lights used by the interactive view. Shared HDRs remain owned by the scene cache during tracing cleanup. Surface textures use private sampler settings and restore without mutating cached source assets. Source/license/download hashes are recorded in `public/exterior-assets/photo/manifest.json` and `vegetation-manifest.json`; `node scripts/download-photo-exterior.mjs` verifies or restores the asset pack. Photography sources: [Suburban Field 01](https://polyhaven.com/a/suburban_field_01), [Industrial Sunset Pure Sky](https://polyhaven.com/a/industrial_sunset_puresky), [Poly Haven asset license](https://polyhaven.com/license).

Untextured procedural Blender meshes can omit UV coordinates in the glTF. For those surfaces, the photo layer creates a private geometry copy with world-metre UV projection. Position and index arrays retain exactly the original values; no topology or dimensions change. Leaving Realistic restores the original geometry object and releases only the temporary copy. Clear-glass lighting refinements also work when the source panel has no UVs. Vegetation can be rebuilt with `node scripts/prepare-photo-vegetation.mjs`; it verifies source downloads and decimates only separate planting assets in background Blender, never the house. Lawn source: [ambientCG Grass 008](https://ambientcg.com/view?id=Grass008), CC0.

This is progressive WebGL2 GPU path tracing, not hardware RTX/DXR acceleration or a 60 FPS ray-tracing guarantee. The actual browser GPU is displayed. No external renderer or remote API is called. The compatible `three-gpu-pathtracer` version is pinned to 0.0.24; `three-mesh-bvh` is pinned to 0.9.8. BVH construction uses a bundled worker. The tracing code is lazy-loaded only when requested. Rendering stops at the selected sample target and while hidden/offscreen. Changes to the displayed design restart accumulation. Unsupported float targets or context failure show an explicit error, with Interactive still available.

Existing Download Villa → Live view snapshot captures the displayed image, including its current ray-tracing convergence. Existing Blender renders/downloads are unchanged.

The neighbourhood ground follows `structuralSizing.plinthHeightMm`, including zero-height and raised houses. The previous fixed 400 mm offset could bury the accepted plot's paving and planters when the house used a taller plinth. This changes only the surrounding presentation ground, not the accepted house.

Performance: the realistic view caches static shadows during orbiting and refreshes them for scene/lighting changes; moving traffic retains dynamic shadows. Dragging uses a lower raster pixel ratio and restores the native ratio after 400 ms of rest. Ray tracing waits 450 ms and updates camera uniforms once after movement, rather than repeatedly resetting accumulation during every drag event. Full-screen denoising/presentation is limited to about six passes per second while tracing continues on every tile; the final image is always presented. Completion is reported once, preventing an idle React/render feedback loop.

Balanced is the default. Its ray buffer is capped at 0.9 megapixels on integrated/unknown GPUs and 1.6 megapixels on NVIDIA/AMD GPUs; Fine uses 1.6/2.4 megapixels. Small views are never upscaled. Photo retains the native drawing-buffer resolution. All modes retain the same eight light and ten transmission bounces and original geometry/textures. Detail changes reuse the BVH and shader instead of rebuilding the whole scene. **View quality** reports actual render dimensions, measured active-movement FPS when available, and refinement time; these are measurements, not FPS guarantees. Initial refinement waits for both photographic surfaces and furnished rooms to finish loading.

Implementation reference: [three-gpu-pathtracer 0.0.24](https://github.com/gkjohnson/three-gpu-pathtracer/tree/v0.0.24). All npm dependencies use their existing licenses.

Checks: `node --experimental-strip-types --test scripts/test-raytrace-performance.mjs scripts/test-photo-exterior.mjs scripts/test-massing-raytrace.mjs scripts/test-elevation-palettes.mjs scripts/test-site-context.mjs`, `npm run lint`, `npm run build`. The scene tests verify world-space extents, visibility, selected colours/maps, resource ownership, camera framing, shipped-asset integrity, zero/raised plinth alignment, pixel budgets, full-resolution Photo and final-frame presentation.
